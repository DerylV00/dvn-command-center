Infrastructure Deep Dive — Section 05

How the engine
actually runs

A full reference document covering every infrastructure option for the Fellowship of Minds agent platform — with architecture diagrams, cost analysis, privacy architecture, and a clear recommendation for each layer of the system.

Bottom line — read this first
The personal agent layer (Deryl + Ken) runs on Base.44 now — the right tool for building and learning. The community layer (Growth House members) requires a Mac Mini running locally the moment it holds sensitive member data — cloud hosting is not acceptable for a private group. The full platform at scale runs a hybrid architecture: local for daily ops, routing, and privacy-sensitive data; frontier AI (Claude API) called only for high-intelligence tasks like deck work, research synthesis, and pattern analysis. This document explains each option in full so every decision is understood — not just followed.

Base.44 is a cloud-hosted super agent platform that lets you build, configure, and communicate with AI agents without managing any infrastructure. You define the agent's context, frameworks, and behavior — Base.44 handles everything underneath. All model inference runs through their API stack, billed per usage. Data lives on their servers. Agents are configured through their interface and can be connected to external tools via integrations. This is where the personal agents for Deryl and Ken are being built right now. It is the fastest way to learn how agents think, how context shapes behavior, and how to communicate to them effectively. It is not where the community layer lives long-term.
What it does well
  • Zero infrastructure — start building agent logic immediately
  • Best learning environment — see how context shapes behavior in real time
  • Frontier AI models — access to the best intelligence available
  • Personal agent phase — ideal for Deryl + Ken while iterating fast
  • Agent communication — teaches you how to write for agents, what context matters
  • Rapid prototyping — test framework loading, accountability logic, pattern detection
Hard limits
  • Credits accumulate fast at scale — not sustainable for community layer
  • All data lives in Base.44's cloud — not acceptable for sensitive member profiles
  • You don't own the infrastructure — if pricing changes, you have no leverage
  • Cannot run always-on background workflows without persistent cost
  • IP dependency risk — platform controls the agent runtime, not you
  • Limited ability to self-host or migrate if platform relationship changes
Best used for
  • Phase 0 — Deryl personal agent build and learning
  • Phase 1 — Ken pilot agent while iterating the framework
  • Prototyping agent logic before committing to local infrastructure
  • Understanding how to structure context for long-term memory agents
  • NOT for community layer — data sensitivity is a hard stop
  • NOT for always-on daily ops at scale — cost compounds

A Mac Mini M2 (or M4) running Ollama is a local AI inference server. Ollama is open-source software that lets you download and run large language models directly on the machine — no cloud, no API bills, no data leaving your network. The Mac Mini runs 24/7, operates as a server, and hosts n8n for workflow automation alongside the local models. This is the critical infrastructure for the community layer — because the moment you're holding sensitive member profiles, Goal logs, shadow patterns, and Wheel of Life data for a private group, that data cannot live on someone else's servers. One-time hardware cost. Zero ongoing inference cost. Full ownership. The tradeoff is model quality — local models (Llama 3.1, Mistral, Qwen) are excellent but not at frontier level. The solution: route simple, repetitive tasks to local, and call the Claude API only for tasks that actually need frontier intelligence.
Hardware recommendation
  • Mac Mini M2 Pro — 16GB unified memory, 512GB SSD (~$700 refurb)
  • Mac Mini M4 Pro — 24GB unified memory, new (~$1,399) — future-proof
  • 16GB minimum — runs Llama 3.1 8B comfortably, 16GB Mistral compressed
  • 24GB+ — runs Llama 3.1 70B quantized, significantly stronger output
  • Ethernet connection recommended — not WiFi — for stable always-on uptime
  • External SSD optional for model storage if 512GB fills up
Software stack on the machine
  • Ollama — local LLM inference server, runs Llama / Mistral / Qwen
  • n8n — workflow automation engine, visual drag-and-drop agent logic
  • Supabase local or PostgreSQL — member database, all profile data
  • Node.js — runtime for Telegram bot webhook handling
  • Cloudflare Tunnel — secure public URL for Telegram webhooks, no port exposure
  • PM2 — process manager, keeps everything running after restart
What local models handle
  • Daily morning context messages — structured, templated, low complexity
  • Weekly check-in generation — reads database, formats accountability message
  • Goal log updates — captures commitments from conversation
  • Pattern flagging — keyword and phrase detection in member messages
  • Event reminders and scheduling — n8n handles trigger logic
  • Member profile updates — structured data entry from conversation
  • Deep framework synthesis — route to Claude API
  • Novel pattern detection requiring judgment — route to Claude API

Hybrid Routing
Local for ops. Frontier AI for intelligence. Intelligent routing decides which engine handles each task.

The hybrid architecture is what the full platform runs at scale. The Mac Mini handles all daily operations — check-ins, reminders, pattern flagging, database reads and writes, Telegram message routing. The Claude API (or GPT-4o) is called selectively for tasks that actually require frontier intelligence — deep research synthesis, complex pattern analysis, framework integration across multiple dimensions, deck and document generation. n8n is the routing brain: it classifies incoming requests, decides which engine handles them, and orchestrates the result back to the member. The result is near-zero marginal cost for daily ops, full frontier power when it matters, and complete ownership of the infrastructure that holds member data.
Routing logic — local vs cloud
  • Local (Ollama): check-ins, reminders, goal logging, profile updates, pattern keyword flags, event messages, structured templates
  • Cloud API: framework synthesis, novel insight generation, complex pattern analysis, document and deck creation, strategic recommendations
  • Routing trigger: task complexity score + data sensitivity flag
  • Sensitive member data never leaves the Mac Mini — only anonymized task context goes to cloud API
  • n8n workflow classifies each incoming message in under 200ms before routing
  • Fallback: if cloud API is unavailable, local handles with reduced depth — never fails silently
Why this wins at scale
  • Daily ops cost approaches zero — Ollama runs inference for free
  • Frontier AI only fires when it earns its cost — ROI per API call is high
  • All sensitive data stays on your hardware — privacy by architecture
  • You own the routing logic — as models improve, you swap them without rebuilding
  • n8n gives visual workflow editing — non-technical team members can adjust flows
  • Scales horizontally — add a second Mac Mini for redundancy if needed
  • Routing logic adds initial build complexity — takes 2–4 weeks to architect properly
  • Requires someone who understands n8n and can maintain workflows

05 — Recommended Architecture

The full system as it should be built.

Not a single option — a phased architecture that uses each tool for what it does best, migrates intelligently as the platform grows, and arrives at full ownership with no legacy debt.

The Fellowship of Minds infrastructure recommendation
Base.44 is the right tool right now — for learning, prototyping, and running the personal agent pilots for Deryl and Ken. Do not migrate away from it until the agent logic is proven and the community layer is ready to deploy. When the community layer opens — the moment Growth House member data starts flowing — a Mac Mini goes live and all sensitive data routes through it exclusively. The hybrid routing architecture is the destination: local for everything that can run locally, frontier AI called surgically for what only frontier AI can do. This is the architecture that makes Fellowship of Minds a defensible SaaS platform with owned infrastructure, owned IP, and zero dependence on any single vendor's pricing decisions.

06 — Privacy Architecture

Why the community layer cannot run on cloud.

The community agent holds some of the most sensitive personal data that exists — shadow patterns, mental models, family dynamics, financial psychology, relationship struggles. The architecture must reflect that weight.

What must never go to a cloud server
  • Member shadow patterns and identified behavioral regressions
  • Wheel of Life scores — these reveal the full map of where someone is struggling
  • Gene Keys shadow activations — deeply personal, not for external logging
  • Goal log — commitments made, commitments missed, renegotiated timelines
  • Pattern log — specific language signals that triggered agent concern
  • Family dynamics, relationship struggles, financial psychology data
  • Anything a member shared in the trust of a private coaching conversation
  • Telegram IDs linked to full identity profiles — PII linkage
What the local architecture guarantees
  • All member data stored on hardware you physically own and control
  • No third-party server ever receives raw member profile data
  • Supabase local instance — database never touches Supabase's cloud servers
  • Ollama inference — no data sent to any external API during local model use
  • When Claude API is called — only anonymized task context is sent, never member PII
  • Cloudflare Tunnel — encrypts transit, does not store or log message content
  • You can tell members: your data lives on our hardware, nowhere else
  • If platform shuts down — data is yours, on your machine, always recoverable
The principle
A private high-trust community operates on one rule: what is shared in the room stays in the room. The infrastructure must enforce that rule technically — not just promise it contractually. Local hosting is not a preference — it is a requirement. The moment member data is on someone else's server, you have made a promise you cannot keep.

08 — Tools Landscape

What every tool actually is.

Three names come up constantly in conversations about AI infrastructure — Ollama, Clawd/OpenClaw, and Antigravity. They are completely different categories of tool. Understanding what each one is — and is not — prevents expensive misrouting of energy and money.

Core infrastructure · Use this
Ollama
Local model runner · Open source · Free
Ollama is the engine that lets you run AI models on your own machine instead of paying a cloud provider per token. Think of it as Docker for AI — you pull a model with one command and Ollama handles everything underneath: memory management, GPU acceleration, quantization, and serving. Once running, it exposes a local API at localhost:11434 that n8n, your Telegram bot, and any other tool can call exactly like they'd call OpenAI — but nothing leaves your machine and every inference costs zero dollars.
This is a core piece of the FOM infrastructure stack. It lives on the Mac Mini and handles all daily ops — check-ins, reminders, pattern flagging, goal logging — at zero marginal cost per run. It is not a platform you interact with directly. It is the engine underneath your agent.
Runs on Mac Mini Zero inference cost Data never leaves machine Phase 2+ stack Llama 3.1 · Mistral · Qwen OpenAI-compatible API GPU + CPU inference 16GB RAM minimum
Watch · Not ready for sensitive data
OpenClaw
Formerly Clawd / Clawdbot · Open source · Autonomous agent
OpenClaw started in November 2025 as a weekend project called Clawd — a playful nod to Anthropic's Claude. Anthropic filed a trademark complaint, it was renamed Moltbot for three days, then became OpenClaw. It is a free, open-source autonomous agent that connects LLMs to your real operating system. It can read and write files, run shell commands, browse websites, send emails, and control APIs. Unlike a chatbot that explains how to do something, OpenClaw actually does it. It exploded to 145,000+ GitHub stars in under three months.
Interesting category, but not ready for FOM community data. Security researchers have already found critical vulnerabilities including a remote code execution flaw. Its broad system access is exactly what makes it powerful — and exactly what makes it risky when holding sensitive member profiles, shadow pattern logs, and family office data. Worth watching as it matures. Not in the stack today.
145K+ GitHub stars Autonomous task execution File · shell · browser · email Security vulnerabilities found Not for sensitive data yet Rapid community growth
Different category · Developer tool
Antigravity
Google · Agent-first IDE · Free preview · Nov 2025
Antigravity is Google's agent-first IDE — a development environment for building software. Released in November 2025 alongside Gemini 3, it is a heavily modified fork of VS Code. Instead of writing code line by line, you issue high-level directives and autonomous agents plan, code, test, and verify entire features across your editor, terminal, and browser. Multiple agents can work in parallel. It supports Gemini 3 Pro, Claude Sonnet 4.6, and OpenAI models. Currently free in public preview.
Antigravity is a tool you would use to build FOM — not a tool that runs inside FOM. A technical developer or technical hire would use Antigravity to write the Telegram bot code, the n8n integrations, and the Supabase schema faster than they could manually. It is not a coaching agent platform. It does not hold member data. It does not run check-ins. The category is completely different. Knowing this distinction saves significant confusion.
Build tool · not a runtime Gemini 3 Pro + Claude 4.6 Multi-agent parallel execution Free public preview Use to BUILD FOM · not run it macOS · Windows · Linux
